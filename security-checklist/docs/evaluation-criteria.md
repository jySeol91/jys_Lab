# 평가기준

이 도구가 진단 점수를 계산하고 조치를 관리하는 기준입니다. 계산에 쓰는 값은 `js/data/rules.js` 한 곳에 모여 있고, 이 문서는 그 근거와 해석을 설명합니다. 고시나 규정이 바뀌면 두 곳을 함께 고칩니다.

- **원문 그대로인 규칙**: 출처의 조문이나 붙임을 그대로 옮긴 것입니다.
- **이 도구의 적용안**: 원문에 없거나 원문이 여러 해석을 허용해서 이 도구가 정한 것입니다. 사내 기준이 있으면 그에 맞게 바꿉니다.

## 1. 근거 문서

| 문서 | 이 도구에서 쓰는 부분 |
| --- | --- |
| 과학기술정보통신부 고시 「주요정보통신기반시설 취약점 분석·평가 기준」(제2025-62호, 2025. 12. 24. 시행) | [붙임4] 점수 산출식, 본문의 개선 구분과 조치불가 취약점 |
| 전자금융감독규정(금융위원회고시 제2026-29호, 2026. 7. 15. 시행) 제37조의2·제37조의3 | 실시 주기, 이행계획, 최고경영자 승인·보고, 결과보고서 |
| 전자금융기반시설 보안 취약점 평가기준(제2025-1호) | 기본 탑재 기준판의 항목과 위험도(1~5) |

금융권 규정(전자금융감독규정)에는 점수 산식이 없습니다. 그래서 점수는 과기정통부 고시 [붙임4]를 빌려 쓰는 내부 관리 지표이고, 고시 본문도 점수 산출을 "할 수 있다"로 정해 의무가 아닙니다. 금융권에서 규정이 요구하는 것은 5장의 기록입니다.

## 2. 점수 산식 (원문 그대로)

출처: 고시 제2025-62호 [붙임4] 취약점 분석·평가 점수 산출식 예시

| 단계 | 내용 |
| --- | --- |
| 항목 배점 | 중요도 상(필수항목) 10점, 중(추가항목) 8점, 하(추가항목) 6점 |
| 진단 결과값 | ○ 취약점 발견: 배점 전부 / P 일부 취약점만 제거: 배점의 절반 / × 취약점 제거: 0점 |
| 영역 점수 | (A − B) ÷ A × 100. A는 모든 취약점이 식별되었을 경우의 점수 합(배점 합), B는 식별된 취약점들의 점수 합(결과값 합) |
| 기술적 영역 | 자산별로 영역 점수를 계산한 뒤, 자산별 점수의 평균(ΣSₙ ÷ N) |
| 합산 | (관리적 점수 × 관리적 항목 수 + 물리적 점수 × 물리적 항목 수 + 기술적 점수 × 기술적 항목 수) ÷ 전체 항목 수 |
| 망분리 비율 | 물리적 분리 100%, 논리적 분리 95%, 미분리 90%. 인터넷 연결이 반드시 필요한 시설은 적용하지 않음 |
| 종합점수 | 합산 점수 × 망분리 비율 |

### 원문 예제와 검증 값

원문 예제의 가정은 다음과 같습니다.

- 관리적 점수 80점(10개 항목), 물리적 점수 70점(5개 항목)
- 기술적 항목 10개, 배점 합 90점, 서버 3대
- 논리적 분리(95%)

| 자산 | 발견 취약점 결과값 합(B) | 자산 점수 |
| --- | --- | --- |
| 서버 1 | 26 | (90 − 26) ÷ 90 × 100 = 71.1 |
| 서버 2 | 20 | (90 − 20) ÷ 90 × 100 = 77.8 |
| 서버 3 | 50 | (90 − 50) ÷ 90 × 100 = 44.4 |

원문은 자산 점수를 71, 78, 44로 반올림해 적었습니다. 나머지는 이 도구가 원문 산식으로 계산한 값입니다.

- 기술적 점수: (71.1 + 77.8 + 44.4) ÷ 3 = 64.4
- 합산: (80 × 10 + 70 × 5 + 64.4 × 10) ÷ 25 = 71.8
- 종합점수: 71.8 × 95% = 68.2

이 예제는 자동 테스트(`tests/assessment.spec.js`)에 그대로 들어 있습니다.

## 3. 이 도구의 적용안

| 주제 | 적용안 | 이유 |
| --- | --- | --- |
| 위험도 1~5 배점 | 5·4·3·2·1을 10·8·6·4·2점으로 매김 | 전자금융 평가기준은 상·중·하가 아니라 위험도 1~5를 씀. 원문 배점(10·8·6)과 같은 간격 |
| 판정 이름 | 양호(×), 취약(○), 부분 조치(P), 해당 없음, 미점검 | 원문 표기에 실무 용어를 붙임 |
| 해당 없음 | 배점 합(A)과 항목 수에서 뺌 | 원문에 규정 없음. 점검 대상이 아닌 항목이 점수를 바꾸지 않게 함 |
| 미점검 | 계산에서 빼고 진단률로 따로 표시 | 진행 중에도 점수를 볼 수 있게 함. 미점검이 남은 점수는 확정값이 아님 |
| 영역 항목 수 | 그 영역에서 한 번 이상 판정된(해당 없음 제외) 항목 수. 기술적 영역은 자산 수를 곱하지 않음 | 원문 예제의 기술적 항목 수가 10(서버 3대 × 10이 아님) |
| 대상 유형 | 기술적 항목에 대상 유형(예: 웹 서비스, 유닉스)을 적으면 같은 유형의 자산에만 적용. 비우면 모든 자산에 적용 | 고시 본문: 특정 시스템은 점검항목을 조정해 점검표를 마련 |
| 관리적·물리적 영역 | 자산과 무관하게 기관 공통으로 한 번 판정 | 원문이 자산별 계산을 기술적 영역에만 둠 |
| 망분리 비율 | 진단마다 선택. 인터넷뱅킹처럼 인터넷 연결이 필수인 서비스는 "미적용" | 원문 단서 |
| 표시 | 계산은 반올림 없이 하고, 화면에는 소수 첫째 자리까지 표시 | 원문 예제는 정수로 반올림해 적음 |
| 배점 합이 0 | "산출 불가"로 표시 | 판정된 항목이 없으면 계산할 수 없음 |

### 판정 기록 기준

- **양호(×)**: 점검 기준에 따른 취약점이 없음
- **취약(○)**: 취약점이 발견됨. 발견 내용을 적음
- **부분 조치(P)**: 발견된 취약점 중 일부만 제거됨. 남은 내용을 적음
- **해당 없음**: 해당 기능이나 구성이 없어 점검 대상이 아님. 사유를 적음

취약, 부분 조치, 해당 없음에 발견 내용이나 사유가 비어 있으면 "기록 누락"으로 세어 진단 화면과 보고서에 표시합니다. 판정은 저장되며 입력을 막지는 않습니다.

## 4. 조치 관리

### 개선 구분과 기본 기한

고시 본문은 위험등급 "상"은 조기에, "중"·"하"는 중기 또는 장기로 개선하도록 정합니다. 이 도구는 이를 다음처럼 적용합니다. 기본 기한은 고시에 일수가 없어 정한 값이므로 `백업·설정` 화면에서 사내 기준으로 바꿔 씁니다.

| 등급 | 개선 구분 | 기본 기한(진단 종료일부터) |
| --- | --- | --- |
| 상 / 위험도 5·4 | 조기 | 30일 |
| 중 / 위험도 3 | 중기 | 90일 |
| 하 / 위험도 2·1 | 장기 | 180일 |

### 조치 상태와 필수 기록

| 상태 | 필수 기록 | 근거 |
| --- | --- | --- |
| 조치 예정 | 없음. 담당자나 조치 기한이 비면 "계획 미수립"으로 표시하고, 기한이 지나면 "기한 초과"로 표시 | 전자금융감독규정 제37조의2제5항 각 호 외의 부분: 이행계획 수립·시행 |
| 조치 완료 | 조치 내용, 완료일(진단 시작일부터 오늘까지), 증적 참조 | 같은 항 제1호: 취약점 제거 또는 상응 조치 |
| 조치불가 | 사유, 보완대책, 최고경영자 승인일, 승인 문서 번호 | 같은 항 제2호: 최고경영자 승인. 고시 본문: 조치불가 증빙자료와 보완대책 |

고시 본문의 조치불가 사유는 "보호조치 방안이 존재하지 않는 경우"와 "조치 시 서비스 중단·장애 등으로 서비스 운영이 불가능한 경우"입니다.

### 이행 현황 지표

- **조치율**: 조치 완료 건수 ÷ 전체 취약·부분 조치 건수
- **조치불가, 기한 초과, 계획 미수립**: 각각 건수로 따로 표시합니다.

이행 결과는 최고경영자 보고(같은 항 제3호)에 쓸 수 있도록 보고서와 엑셀 파일에 함께 담깁니다.

## 5. 금융권 규정이 요구하는 것

출처: 전자금융감독규정(금융위원회고시 제2026-29호) 제37조의2, 제37조의3. 조문을 요약한 것이므로 정확한 문구는 원문을 확인합니다.

| 조문 | 내용 | 이 도구의 반영 |
| --- | --- | --- |
| 제37조의2제1항·제3항 | 연 1회 이상 실시. 홈페이지는 6개월에 1회 이상 | 자산·주기 화면: 마지막 진단 종료일부터 12개월(홈페이지 6개월)을 다음 기한으로 보수적으로 계산하고, 30일 이내 도래와 기한 초과를 표시 |
| 제37조의2제2항 | 자체전담반(정보보호최고책임자 포함 5인 이상) 구성. 평가전문기관에 위탁하면 예외 | 진단마다 수행 주체(자체·위탁)와 수행 조직을 기록 |
| 제37조의2제4항 | 주기 안에서 평가 대상 시설과 기간을 나누어 평가할 수 있음 | 한 기준판으로 진단을 여러 건 만들 수 있고, 자산별 마지막 진단일을 따로 계산 |
| 제37조의2제5항 | 이행계획 수립·시행: 취약점 제거 또는 상응 조치, 불가 시 최고경영자 승인, 시행 결과 최고경영자 보고 | 조치 관리 화면과 4장의 필수 기록 |
| 제37조의3제2항 | 결과보고서를 금융위원장에게 제출 | 보고서 화면(인쇄·PDF 저장)과 엑셀 내보내기. 공식 서식은 아니므로 제출 서식에 옮겨 씀 |

## 6. 기준판 개정과 재점검

- 새 기준판을 등록하면 같은 계열에서 직전에 등록한 판과 비교해 추가·변경·삭제·문구 변경을 표시합니다.
- **변경**은 영역, 대상 유형, 분류, 항목명, 등급, 점검 내용, 판단 기준 중 하나가 달라진 항목입니다. 다시 점검해야 합니다. 배점 방식이 바뀌면 두 판에 모두 있는 항목을 전부 변경으로 봅니다.
- **문구 변경**은 대응 방안, 조치 시 영향, 원문 위치, 비고만 달라진 항목입니다. 비어 있던 점검 내용·판단 기준을 채운 것(보강)도 문구 변경으로 봅니다. 다시 점검하지 않아도 됩니다.
- 기존 진단은 처음 적용한 기준판을 계속 참조합니다.
- "새 기준판으로 이어서 진단"을 쓰면 바뀌지 않은 항목의 판정과 조치 기록을 이어받습니다. 추가·변경 항목은 미점검으로 표시합니다.
- 고시 본문의 "직전년도에 발견된 취약점은 중점적으로 확인"에 따라, 이어받은 진단에서 이전 진단의 취약 항목을 따로 표시합니다.
