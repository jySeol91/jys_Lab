# 취약점 진단 평가

점검 기준 문서를 **기준판**으로 등록하고, 자산별로 항목을 판정해 점수를 내고, 취약 항목의 조치를 관리하는 브라우저 도구입니다.

- **점수**: 과학기술정보통신부 고시 「주요정보통신기반시설 취약점 분석·평가 기준」(제2025-62호) [붙임4] 산식을 씁니다.
- **조치 관리**: 전자금융감독규정 제37조의2·제37조의3이 요구하는 이행계획, 최고경영자 승인·보고, 실시 주기를 기록합니다.
- **구현**: HTML·CSS·순수 JavaScript만 쓰고, 빌드 단계도 서버 측 저장도 없습니다. 기록은 브라우저 로컬 저장소에 남습니다.

평가 기준과 산식의 근거, 이 도구가 정한 적용안은 [docs/evaluation-criteria.md](docs/evaluation-criteria.md)에 정리했습니다.

## 실행

### 방법 1. 파일 직접 열기

`index.html`을 브라우저(Chrome, Edge, Firefox, Safari 최신판)로 엽니다. 설치할 것이 없습니다.

### 방법 2. 로컬 서버

```bash
python3 -m http.server 4173
```

브라우저에서 <http://localhost:4173/> 을 엽니다. `npm start`도 같은 명령입니다. Windows에서 `python3`가 없으면 `python -m http.server 4173`으로 실행합니다.

> 두 방법은 브라우저가 서로 다른 저장 공간으로 취급해 기록이 이어지지 않습니다. 옮기는 방법은 [기록 옮기기](#기록-옮기기)를 보세요.

## 사용 순서

1. **기준판**: 기본으로 전자금융기반시설 2025 WEB 점검항목 48개가 들어 있습니다. 다른 기준이나 새 판은 엑셀 양식으로 등록합니다.
2. **자산·주기**: 점검할 자산(웹 서비스, 서버 등)과 유형을 등록합니다. 홈페이지는 6개월 주기로 표시됩니다.
3. **진단 평가**: 진단을 만들고 기준판과 대상 자산을 고릅니다.
   - 항목마다 양호·취약·부분 조치·해당 없음을 판정하고 발견 내용과 증적을 적습니다. 입력하는 즉시 저장되고 점수가 바뀝니다.
   - 관리적·물리적 항목은 기관 공통으로 한 번, 기술적 항목은 자산마다 판정합니다.
4. **조치 관리**: 취약·부분 조치 칸마다 담당자, 기한, 조치 내용을 기록합니다. 조치 완료와 조치불가(최고경영자 승인)는 필수 기록이 있어야 저장됩니다.
5. **보고서**: 점수, 판정 요약, 취약 항목과 대응 방안, 이행계획을 보여 줍니다. 인쇄해서 PDF로 저장하거나 엑셀로 내려받습니다.

## 기준이 바뀔 때 (연도별 개정)

1. **기준판** 화면의 **문서를 엑셀 양식으로 변환**에 새 문서(docx 또는 hwpx)를 넣습니다.
   - 항목, 점검 내용, 판단 기준, 대응 방안을 표에서 읽어 엑셀 양식 초안을 만듭니다.
   - 원문의 항목ID 누락, 등급 불일치, 그림 같은 확인할 내용을 함께 알려 줍니다.
   - 한글 hwp는 hwpx로, PDF는 Word로 저장해서 넣습니다.
2. 내려받은 엑셀에서 기준정보(연도·버전·출처)와 확인할 내용을 고칩니다. 작성 방법은 양식의 **작성 안내** 시트에 있습니다.
3. **엑셀 양식으로 등록**에 넣으면, 같은 계열에서 직전에 등록한 판과 비교해 추가·변경·삭제·문구 변경을 보여 줍니다. 확인한 뒤 등록합니다.
4. 기존 진단은 처음 고른 기준판을 그대로 씁니다. **진단 평가 → 새 기준판으로 이어서 진단**을 쓰면 바뀌지 않은 항목의 판정과 조치 기록을 이어받고, 추가·변경 항목만 다시 점검합니다.

사내 점검 지표도 같은 엑셀 양식으로 만들면 똑같이 등록하고 평가할 수 있습니다. 빈 양식은 **기준판 → 빈 엑셀 양식 내려받기**로 받습니다.

## 테스트

Node.js 18 이상과 Python 3이 필요합니다.

```bash
npm install
```

```bash
npx playwright install chromium
```

```bash
npm test
```

`npm test`는 로컬 서버(4173 포트)를 띄우고 Chromium으로 `tests/assessment.spec.js`를 실행합니다. 다음을 검증합니다.

- [붙임4] 원문 예제 점수 재현: 자산 71.1·77.8·44.4점, 종합 68.2점
- 진단 만들기 필수값과 KST 날짜
- 판정에 따른 점수·진단률 갱신, 기록 누락 표시
- 문서 변환: docx의 글상자 중복, 항목ID 누락, 그림 / hwpx의 영역·대상 유형·병합 칸
- 대상 유형에 따른 자산별 적용
- 기준판 개정 비교와 기존 진단의 기준판 유지, 개정판으로 이어서 진단
- 조치 완료·조치불가 필수값, 기한 초과, 조치율
- 연 1회·6개월 주기 계산
- 새로고침 후 유지, JSON 백업 왕복, 이전 점검표 기록 가져오기
- 양식 오류 표시, `file://` 실행, 보고서와 엑셀 내보내기

테스트용 예시 문서는 `python3 tests/fixtures/make_fixtures.py`로 다시 만들 수 있습니다. 내용은 모두 가상입니다.

리눅스에서 로캘이 UTF-8이 아니면 브라우저가 한글 파일 이름을 `download`로 바꿉니다. 그래서 `playwright.config.js`가 테스트용 브라우저만 UTF-8 로캘로 띄웁니다.

## 저장과 기록 옮기기

### 저장 위치

- 로컬 저장 키는 `security-assessment-ko-v1`입니다.
- 이전 '보안 이슈 대응 점검표'의 키(`incident-checklist-ko-v1`)는 읽기만 하고 지우지 않습니다.
- 이전 점검표의 기준판은 **백업·설정 → 기준판 가져오기**로 가져옵니다. 사고 대응 기록은 가져오지 않습니다.

### 기록 옮기기

브라우저 저장소는 주소별로 나뉩니다. 파일 직접 열기(`file://…`), `http://localhost:4173`, `http://127.0.0.1:4173`, 다른 브라우저나 프로필은 모두 다른 저장 공간입니다. 기록이 안 보이면 지워진 것이 아니라 다른 저장 공간을 보고 있는 것입니다.

1. 기록이 있는 쪽을 예전과 같은 방식으로 엽니다.
2. **백업·설정 → JSON 백업 내려받기**를 누릅니다.
3. 옮겨 갈 쪽을 열고 **백업·설정 → JSON에서 복원**으로 그 파일을 고릅니다.
4. 확인 창에서 계속을 누릅니다. 옮겨 갈 쪽의 기록은 백업 내용으로 **통째로 바뀌며 합쳐지지 않습니다.**
5. 옮긴 뒤에는 한쪽만 계속 씁니다.

## 주의

- 이 저장소는 공개 저장소입니다. 내부 점검 지표 문서, 변환한 엑셀, 진단 결과(JSON 백업, 보고서)는 저장소에 올리지 마세요. 도구는 문서를 브라우저 안에서만 읽고 어디에도 보내지 않습니다.
- 보고서는 공식 제출 서식이 아닙니다. 결과보고서를 작성할 때 내용을 옮겨 씁니다.
- 기본 탑재 기준판에는 항목 목록과 위험도만 있습니다. 점검 내용·판단 기준·대응 방안은 원문 문서를 변환해 새 판으로 등록하면 진단 화면과 보고서에 함께 나옵니다.
- 문서 변환은 표를 읽는 방식이라 그림, 표 밖에 쓴 내용, 모양이 많이 다른 표는 옮기지 못할 수 있습니다. 반드시 엑셀에서 검토한 뒤 등록합니다.
